## Part B — Portfolio Architecture

### 1. On-Chain Ownership Discovery Strategy (No `ERC721Enumerable`)

`SavingCore` implements OpenZeppelin `ERC721` without `ERC721Enumerable` to conserve deployment bytecode and runtime gas. Therefore, `tokenOfOwnerByIndex` is not available.

The portfolio data discovery layer (`frontend/src/lib/portfolio.ts`) operates strictly on-chain:

1. **Total Count Query**: Reads `depositCount = Number(await savingCore.depositCount())`.
2. **System Parameter Query**: Reads `gracePeriodSeconds = Number(await savingCore.gracePeriodSeconds())`.
3. **Blockchain Clock Snapshot**: Fetches latest block timestamp `provider.getBlock("latest").timestamp` to serve as the absolute financial time authority.
4. **Bounded Batch Ownership Scan**:
   - Iterates through token IDs `[1 ... depositCount]` in chunks of 10.
   - Queries `ownerOf(id)` concurrently per chunk.
   - Identifies token IDs where `ownerOf(id).toLowerCase() === connectedWallet.toLowerCase()`.
   - Never uses `localStorage` or session cache as a source of truth for portfolio ownership.
5. **Deposit Data Enrichment**:
   - For all owned token IDs, calls `getDeposit(id)` to retrieve snapshot terms (`principal`, `startAt`, `maturityAt`, `aprBpsAtOpen`, `penaltyBpsAtOpen`, `status`).
   - Normalizes terms to native BigInt values and computes exact mathematical interest and penalty amounts.

### 2. Event-Driven Lineage Tracing

To visualize multi-cycle renewal ancestry ($#1 \to #2 \to #3$) without altering contract storage:

- Queries `savingCore.filters.Renewed()` logs from block 0 to `"latest"`.
- Extracts `oldDepositId` and `newDepositId` from the indexed args.
- Constructs deterministic bidirectional lineage maps (`renewedToMap` and `renewedFromMap`).
- Links parent and successor certificates directly in the frontend model.

### 3. Data Models

Defined in `frontend/src/types/index.ts`:

### 4. Reactive Refresh Triggers

The portfolio auto-refreshes on:

- Wallet account connected or changed (`accountsChanged`).
- Blockchain network switched (`chainChanged`).
- Contract deployment reloaded.
- Financial transaction confirmed (Deposit opened, Early withdrawal, Maturity withdrawal, Manual renewal, Auto renewal).
- User clicking the "Refresh Portfolio" action.

## Part D — Financial & Time Eligibility Matrix

| Action                | Time Requirement ($t$)       | Status       | Caller Requirement          | Vault Status      | Target Plan Precondition                      | Financial Outcome                                                                                                                   |
| :-------------------- | :--------------------------- | :----------- | :-------------------------- | :---------------- | :-------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------- |
| **Early Withdraw**    | $t < M$                      | `Active` (0) | Current `ownerOf(id)`       | `paused == false` | N/A                                           | Owner receives $P - F$<br/>FeeReceiver receives $F$<br/>Status $\to$ `Withdrawn` (1)                                                |
| **Maturity Withdraw** | $t \ge M$                    | `Active` (0) | Current `ownerOf(id)`       | `paused == false` | N/A                                           | Owner receives $P + I$<br/>Vault transfers $I$<br/>Status $\to$ `Withdrawn` (1)                                                     |
| **Manual Renew**      | $t \ge M$                    | `Active` (0) | Current `ownerOf(id)`       | `paused == false` | `enabled == true`<br/>$min \le P + I \le max$ | Old status $\to$ `ManualRenewed` (2)<br/>New deposit minted to owner<br/>New principal $= P + I$<br/>Target plan terms applied      |
| **Auto Renew**        | $t \ge G = M + \text{grace}$ | `Active` (0) | Permissionless (any wallet) | `paused == false` | N/A (locks old snapshot terms)                | Old status $\to$ `AutoRenewed` (3)<br/>New deposit minted to old owner<br/>New principal $= P + I$<br/>Old APR/tenor/penalty locked |

## Part I — Portfolio Ownership & Lineage Retention

1. **Transfer Sensitivity**:
   - Ownership is determined by `ownerOf(depositId)`, never original depositor from event logs.
   - When Alice transfers Certificate `#1` to Bob, refreshing Alice's view removes `#1`, and Bob's view discovers `#1`.
   - Only Bob holds the authority to settle or manually renew `#1`.
2. **Historical Retention**:
   - Terminal certificates (`Withdrawn`, `ManualRenewed`, `AutoRenewed`) are never burned or hidden.
   - They remain permanently recorded in the Certificate History tab with full terms and transaction receipts.
3. **No Double Settlement Claims**:
   - Calling `withdrawAtMaturity` or `renewDeposit` on a terminal certificate reverts immediately with custom error `DepositNotActive(depositId, currentStatus)`.

## Part J — Transaction Lifecycle & Error Decoding

Financial actions proceed through a strict state machine:
$$\text{idle} \to \text{validating} \to \text{awaiting-signature} \to \text{pending} \to \text{success} \text{ or } \text{error}$$

### Custom Error Decoding Table

| Solidity Error                          | Human-Readable Feedback in UI                                                                                 |
| :-------------------------------------- | :------------------------------------------------------------------------------------------------------------ |
| `NotDepositOwner(id, caller)`           | "Action rejected: Only the current owner of this deposit NFT certificate can perform this action."            |
| `DepositNotFound(id)`                   | "Deposit record was not found on-chain."                                                                      |
| `DepositNotActive(id, status)`          | "This deposit is no longer active (it has already been withdrawn or renewed)."                                |
| `DepositNotMatured(id, maturityAt)`     | "Deposit has not reached maturity yet. Maturity withdrawal and manual renewal require t >= maturityAt."       |
| `EarlyWithdrawalClosed(id, maturityAt)` | "Early withdrawal is closed because the deposit has already reached or passed maturity."                      |
| `GracePeriodNotEnded(id, graceEnd)`     | "Auto-renewal grace period has not ended yet. Auto-renewal is only available after the grace period expires." |
| `DepositAmountOutOfRange(...)`          | "Deposit principal is outside the allowed minimum and maximum deposit limits for this plan."                  |
| `PlanDisabled(planId)`                  | "This saving plan is currently disabled by Bank Admin and cannot accept new deposits."                        |
| `EnforcedPause()`                       | "The banking vault is currently paused by Bank Admin."                                                        |
| `CoreNotBound(...)`                     | "Protocol integrity error: SavingCore is not bound to VaultManager."                                          |
| `InsufficientVaultBalance`              | "Banking vault has insufficient liquidity reserves to disburse interest."                                     |
| `ACTION_REJECTED` / `4001`              | "Transaction was cancelled in your wallet."                                                                   |
