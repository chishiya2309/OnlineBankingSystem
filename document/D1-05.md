## Part B — VaultManager Implementation

Vault kế thừa Ownable, Pausable và ReentrancyGuard từ OpenZeppelin; ERC20 transfers dùng SafeERC20. Storage nghiệp vụ chỉ gồm `IERC20 public immutable token`, `address public savingCore` và `address public feeReceiver`; owner/paused dùng inherited storage. Liquidity đọc trực tiếp `token.balanceOf(address(this))`, không dùng balance counter.

Constructor nhận `(address token_, address admin_, address feeReceiver_)`. Helper `internal pure _validateAdmin` chạy trước Ownable để admin zero trả đúng `ZeroAddress()` như D1-03, thay vì lỗi mặc định của Ownable. Constructor kiểm tra token/fee receiver nonzero, token có code và metadata decimals bằng 6. Token không đổi sau deployment; ban đầu unpaused, savingCore zero và Vault không có tiền. Không mint hoặc tự fund trong constructor.

| Function | Quyền / guards | Hành vi |
| --- | --- | --- |
| `setSavingCore(core)` | onlyOwner; chưa bind; core nonzero có code | Bind đúng một lần; already-set check chạy trước validation địa chỉ mới |
| `fundVault(amount)` | onlyOwner, nonReentrant; amount > 0 | safeTransferFrom current admin vào Vault; được khi paused/chưa bind |
| `withdrawVault(amount)` | onlyOwner, whenNotPaused, nonReentrant; amount > 0 và <= actual balance | safeTransfer về current admin; không reserved-interest check |
| `setFeeReceiver(receiver)` | onlyOwner; receiver nonzero | Thay địa chỉ, không chuyển token; được khi paused; emit kể cả cùng receiver |
| `pause()` / `unpause()` | onlyOwner; trạng thái phù hợp Pausable | Chặn/khôi phục financial outflows; không chặn funding/configuration/reads |
| `payInterest(amount)` | onlySavingCore, whenNotPaused, nonReentrant; amount > 0 và đủ balance | Chỉ safeTransfer đến savingCore đã lưu; không có recipient/allowance parameter |
| `transferOwnership(newOwner)` | Inherited Ownable | Chuyển Bank Admin duy nhất; owner cũ mất quyền |
| `renounceOwnership()` | public override onlyOwner, nonpayable | Luôn revert `OwnershipRenounceDisabled()` |

Events khai báo đúng Part H1: `SavingCoreSet`, `VaultFunded`, `VaultWithdrawn`, `FeeReceiverUpdated`, `InterestPaid`, với indexed fields tương ứng. Events tài chính emit sau ERC20 transfer thành công. OwnershipTransferred, Paused và Unpaused dùng OpenZeppelin.

Custom errors đúng Part H2: `ZeroAddress()`, `InvalidContract(address account)`, `InvalidTokenDecimals(uint8 actual)`, `SavingCoreAlreadySet(address currentCore)`, `UnauthorizedSavingCore(address caller)`, `AmountZero()`, `InsufficientVaultBalance(uint256 available,uint256 required)` và `OwnershipRenounceDisabled()`. Các lỗi owner/pause/reentrancy/ERC20 còn lại dùng OpenZeppelin.

## Part C — Interface Compatibility

[IVaultManager](../contracts/interfaces/IVaultManager.sol) có đúng sáu functions:

```solidity
function token() external view returns (IERC20);
function owner() external view returns (address);
function savingCore() external view returns (address);
function feeReceiver() external view returns (address);
function paused() external view returns (bool);
function payInterest(uint256 amount) external;
```

Smoke đã so sánh full function fragments của interface và Vault artifact: cả sáu đều khớp inputs/outputs/mutability. IERC20 return type được ABI encode thành address. Artifact Vault có đúng 14 functions trong D1-03, không có endpoint payout bổ sung; renounceOwnership vẫn nonpayable. Năm events và tám custom errors cũng được đối chiếu field names/types/indexed flags.

Vault không kế thừa trực tiếp interface, tránh overrides thừa cho inherited getters. Caller mock import IVaultManager, compile và gọi thành công `payInterest`, chứng minh interface được contract khác sử dụng. Tích hợp với SavingCore production: **Not Executed**, thuộc task sau.

### Issues và xử lý

- Compiler warning: `Function state mutability can be restricted to view` tại renounceOwnership. Giữ nonpayable theo ABI D1-03/kế hoạch được chốt, không thêm state write giả hoặc đổi interface chỉ để che warning. Hàm luôn revert; smoke xác nhận exact error và nonpayable ABI. Đây là warning đã biết, không phải lỗi compile hoặc blocker.
- Typecheck ban đầu có hai TS2345 do TypeChain chỉ nhận literal function/event names, còn vòng lặp ABI dùng string động. Đã dùng reference có type chuẩn ethers `Interface` cho phần inspection, giữ generated types cho contract calls. Typecheck cuối và smoke chạy lại đều PASS.
- Không phát hiện blocker bảo mật/kỹ thuật trong phạm vi đã kiểm chứng. Chưa thực hiện security audit đầy đủ hoặc adversarial unit tests.
